# Managed Pro 手动 QA 测试单

日期：2026-05-14

## 使用范围

本测试单只测试 `managed pro`。

不要测试 `self-managed/open-source`。

测试开始时默认使用一个空 vault。这个 vault 里不应该有任务、记忆、提醒、草稿、上传文件或历史聊天。

## 记录规则

每条用例只记录一个结果：

- `PASS`：所有通过标准都满足。
- `FAIL`：页面行为和通过标准不一致。
- `BLOCKED`：账号、网络、入口、测试文件或页面不可用，导致无法继续。

出现 `FAIL` 时，截图并记录：

- 用例编号。
- managed pro 测试账号。
- 输入的文字。
- 发生时间。
- 看到的问题。

出现 `BLOCKED` 时，记录缺少什么或卡在哪一步。

测试文件已经准备在当前项目目录：

- `docs/qa-assets/qa-ocr-sample.png`

附件存储清理用例需要测试环境里已有或预置 cloud attachment inventory，至少包含图片、PDF、音频、视频四类条目。如果缺少某一类，只把对应预览步骤记为 `BLOCKED`，不要临时改 App 数据库或测试配置。

## 开始前准备

### QA-SETUP-01 清空并启动 App

前置条件：

- 已拿到 managed pro 测试账号。
- 已确认这个账号对应的是空 vault。
- 已关闭 SecondLoop App。

操作步骤：

1. 打开终端。
2. 进入当前项目目录。
3. 执行：

```bash
pixi run reset-local-dev-data
```

4. 执行：

```bash
pixi run run-macos
```

5. 等待 App 打开。

通过标准：

- App 能打开。
- App 没有自动进入旧账号。
- App 没有显示上一轮测试留下的聊天、任务或提醒。

失败记录：

- 如果命令失败，复制最后看到的错误文字。
- 如果 App 打不开，截图。

### QA-SETUP-02 登录 managed pro

操作步骤：

1. 在 App 中登录 managed pro 测试账号。
2. 进入 `Settings` 或 `设置`。
3. 打开运行模式相关页面。
4. 选择 `managed pro`。
5. 按页面提示完成连接。
6. 回到 Chat 页面。
7. 打开任务列表。
8. 打开记忆页面。
9. 打开提醒页面。

通过标准：

- 登录成功。
- `managed pro` 显示已连接或可用。
- Chat 页面可以打开。
- 任务列表为空。
- 记忆页面为空。
- 提醒页面为空。

失败记录：

- 截图登录或连接失败页面。
- 如果任务、记忆或提醒不为空，记 `BLOCKED`，不要继续后续用例。

## Chat 和任务

### QA-CHAT-01 创建普通任务

操作步骤：

1. 打开 Chat。
2. 在输入框粘贴：

```text
帮我创建一个任务：完成周报。
```

3. 发送。
4. 等待助手回复完成。
5. 打开任务列表。

通过标准：

- 助手明确表示任务已创建，或页面显示创建成功。
- 任务列表出现 `完成周报`。
- `完成周报` 不是已完成状态。
- 页面没有要求先批准。
- 如果只在 Chat 里看到 `完成周报` 卡片，但任务列表没有出现 `完成周报`，记 `FAIL`。

失败记录：

- 截图助手回复。
- 截图任务列表。

### QA-CHAT-02 修改任务必须先确认

前置条件：

- 已完成 `QA-CHAT-01`。
- 任务列表中有未完成任务 `完成周报`。

操作步骤：

1. 打开 Chat。
2. 在输入框粘贴：

```text
把“完成周报”改到今天 20:00，但不要标记完成。
```

3. 发送。
4. 等待助手回复完成。
5. 不要点击批准或确认。
6. 打开任务列表，查看 `完成周报`。
7. 回到 Chat。
8. 点击批准或确认。
9. 再次打开任务列表，查看 `完成周报`。

通过标准：

- 第 4 步后，页面出现需要确认的卡片或按钮。
- 第 6 步时，`完成周报` 没有被标记完成。
- 第 6 步时，正式时间还没有被改掉，或页面明确显示仍在等待确认。
- 第 9 步时，任务时间显示为今天 20:00，或等价的今天晚上 8 点。
- 第 9 步时，`完成周报` 仍然不是已完成状态。

失败记录：

- 截图确认前的任务。
- 截图确认后的任务。

### QA-CHAT-05 普通聊天使用搜索技能并承接上一轮话题

操作步骤：

1. 打开 Chat。
2. 确认当前 runtime 的 enabled skill catalog 中包含 `web-research`，或测试环境有等价的搜索/调研技能可用。
3. 输入：

```text
Apple 今天的发布会发布了哪些产品？
```

4. 等待助手回复。
5. 输入：

```text
介绍一下新的手机产品参数。
```

6. 等待助手回复。

通过标准：

- 第一轮回答必须通过 `web-research` 或等价搜索技能获取当前公开信息，不能只依赖模型自身知识。
- 第一轮回答应显示来源链接或来源列表；如果搜索技能不可用，必须明确提示不可用，本用例记 `BLOCKED`，不能按通过处理。
- 助手能理解“新的手机产品”指上一轮 Apple 发布会里的手机产品。
- 助手不应要求用户重新说明是哪几个产品。
- 第二轮回答应继续基于上一轮搜索结果、conversation context 或必要的补充搜索生成参数说明。
- 如果没有可验证来源，助手必须说明无法准确确认，不能编造发布产品或参数。

失败记录：

- 截图两轮用户输入和助手回复。
- 记录 runtime tool trace 中是否出现 `web-research` 或等价搜索技能调用。
- 如果助手追问“新的手机产品”是什么，记 `FAIL`。
- 如果助手直接给出最新发布信息但没有来源或 tool trace，记 `FAIL`。

## 笔记和附件存储

### QA-NOTE-01 在线创建和编辑笔记

操作步骤：

1. 确认 App 已连接 managed pro。
2. 打开 Notes 或笔记入口。
3. 新建一篇笔记，标题输入 `QA 在线笔记`。
4. 正文输入 `第一版正文。`。
5. 点击保存，等待状态显示已保存。
6. 把正文改为 `第二版正文，来自在线编辑。`。
7. 再次保存。
8. 离开笔记页面后重新打开这篇笔记。

通过标准：

- 新笔记能保存成功。
- 重新打开后标题仍是 `QA 在线笔记`。
- 重新打开后正文包含 `第二版正文，来自在线编辑。`。
- 页面没有要求配置 Rust、本地 runtime、WebDAV 或本地同步目录。

失败记录：

- 截图保存状态，以及重新打开后的标题和正文。

### QA-NOTE-02 离线编辑显示待同步并在重连后同步

前置条件：
- 已完成 `QA-NOTE-01`。

操作步骤：

- 离线保存不会丢失正文。
- 第 7 步后状态变为已保存或干净状态。
- 重连后重新打开笔记，正文包含 `第三版正文，来自离线编辑。`。
- 页面没有提示执行本地-first vault 同步。

失败记录：

### QA-NOTE-03 版本冲突显示本地和远端正文

前置条件：
- 测试环境可以用另一台设备、另一个 App 窗口或 runtime fixture 修改同一篇笔记的远端版本。
- 如果无法制造远端并发修改，记 `BLOCKED`。

操作步骤：

1. 在当前 App 打开 `QA 在线笔记`。
2. 断开当前 App 网络。
3. 在另一端把同一篇笔记正文改为 `远端冲突正文。`。
4. 回到当前 App，把正文改为 `本地冲突正文。`。
5. 保存当前 App 的离线编辑。
6. 恢复当前 App 网络。
7. 等待同步完成或失败提示出现。

通过标准：

- 页面进入冲突状态，不能静默覆盖远端正文。
- 冲突区域能看到 `本地冲突正文。`。
- 冲突区域能看到 `远端冲突正文。`。
- 本地正文和远端正文都能滚动查看，不会被遮挡。

失败记录：

- 截图冲突状态，以及本地和远端正文同时可见或可滚动查看的位置。

### QA-ATTACH-02 预览图片、PDF、音频和视频附件

前置条件：
- 测试 vault 的附件列表里有图片、PDF、音频、视频四类条目。

### QA-ATTACH-03 删除附件前显示影响确认

失败记录：

- 截图删除影响确认、取消后仍存在、确认删除后列表变化。

- 如果循环提醒候选标题仍显示为“孩子生日”或类似弱标题，但卡片内容仍能看出它是“每年生日前一天提醒买礼物”，继续执行 `QA-REM-02A`，同时记录标题理解偏弱。

- 如果出现循环提醒候选但没有记忆候选，记 `FAIL`。

失败记录：
